# C-002 verification record

Baseline `g1-design-v2.0` at `9edbcd4b9a142d107df219bc64bd6730b39689cd`. Verified November 10, 2026.

## Delivered behavior

- Alembic revision `0003_storage_contract` backfills `runs.project_id` from each run's conversation and makes it required.
- Composite keys and foreign keys enforce that a run's owner, project, conversation, and question message belong to one valid scope. New run writes persist the authenticated conversation's project ID.
- Fresh migration no longer installs or requires pgvector. Existing prototype databases retain any already-installed extension, while the P0 schema runs on vanilla PostgreSQL 16.
- Message and model-response digests must be lowercase 64-character SHA-256 hex values. Messages, model responses, and audit events reject update or delete operations at the database layer.
- Migration connections use no persistent SQLAlchemy pool, so isolated upgrades release their database before cleanup. Applying the head revision twice is safe.
- The migration is forward-only. Operational rollback remains restoration of a verified pre-upgrade backup into an isolated database, as frozen in the adoption contract.
