# C-003 verification record

Baseline `g1-design-v2.0` at `9edbcd4b9a142d107df219bc64bd6730b39689cd`. Verified November 10, 2026.

## Delivered behavior

- Owner sessions are stored only as hashes, expire durably, revoke on logout, and cannot be replayed after revocation. Cookie flags remain HttpOnly and SameSite=Strict, and Secure is enabled for HTTPS deployments.
- State-changing requests require the exact configured Origin. Authentication failures use generic client messages, and unexpected failures return a sanitized problem response correlated by `X-Trace-ID` without logging exception content.
- Failed logins are counted in durable PostgreSQL state and serialized per owner. Five failures in fifteen minutes return a stable rate-limit response; successful authentication clears the throttle.
- Project, conversation, message, run, and import access is checked within the authenticated owner and project scope before returning a resource. Guessed foreign UUIDs and mixed nested targets remain invisible.
- Alembic revision `0004_security_audit` adds typed audit actions and outcomes, project scope, a schema version, and durable login-throttle storage. New audit evidence must use schema version 1. Update, delete, and truncate are rejected at the database layer.
- Existing recognized historical events are backfilled to typed version 1 rows. Ambiguous legacy events are retained as version 0 with an explicit `unknown` outcome; new version 0 inserts are rejected. The compatibility trigger derives only unambiguous outcomes for an older deployed writer during a rolling upgrade.
- Business and audit writes share one transaction. A forced unexpected exception rolls both back and does not expose or log a canary secret.

## Requirements and limits

This verifies the C-003 portions of FR-018, NFR-005, NFR-006, NFR-013, P0-02, and P0-23. It covers login/session handling, request-origin enforcement, owner/project resource invisibility, audit typing/immutability, transactional rollback, and runtime error redaction.

The full portable-export leak assertion in P0-02 remains assigned to C-015. Cross-feature authorization and audit cases in P0-23 remain open for the features delivered by C-010, C-013, and C-014. OIDC, multiple owners/tenants, internet exposure, and P1/P2 work are outside the frozen P0 scope.

No frozen public API contract changed and no Change Request was required. The development database was not migrated, replaced, or promoted during this task; all destructive migration and browser checks ran in disposable isolated databases.
