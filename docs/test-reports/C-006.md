# C-006 verification record

Baseline `g1-design-v2.0` at `9edbcd4b9a142d107df219bc64bd6730b39689cd`. Verified November 13, 2026. The durable checkpoint uses commit message `C-006 freeze provider identity snapshots` and includes this record with the implementation and state indexes.

## Delivered behavior

- The provider registry now records provider and alias, gateway and routing, acquisition path, declared application, configured model, family, unique capabilities, pricing status/version, privacy profile, verification time, identity confidence, and enabled state. The existing manual path remains enabled and local-only.
- Gemini is present only as a disabled `google/gemini-api-candidate` registry entry. It has no configured or resolved model, verification date, price version, entitlement, or dispatch path; privacy remains blocked and pricing remains unknown.
- New run targets receive an immutable database-enforced registry snapshot at insertion. The trigger is authoritative, rejects disabled/missing selections, preserves compatibility with the old six-column writer, and prevents later edits or reassignment of target identity and run linkage.
- Legacy targets are migrated without copying the catalog's later state: their historical registry status is `unknown`, unobserved labels and verification facts stay null, and only facts inherent to the stored manual route are retained. Legacy catalog entries without complete qualification are disabled with unknown/blocked metadata.
- Original-response storage now has nullable resolved provider/model, returned version, manual declarations, elapsed time, token counts, actual cost, context snapshot, attempt number, and inclusion. Unknown measured values remain null; manual rows do not gain API-attested identity; raw content, Unicode, whitespace, hashes, and prior compatibility fields remain unchanged.
- Verified family counting requires included official-API evidence with provider-reported, nonblank, nonsentinel resolved provider/model and known family. Aliases resolving to one normalized family count once; manual, unresolved, unknown, multi-model, and late-excluded evidence earns no confirmation.
- Public registry and original-detail response models enforce the frozen bounds, enums, unique capabilities, nullable measurements, nonnegative counters, and source-digest format. Stored provider output has no manual-input size ceiling.
- Database checks mirror the public string and measurement rules, including raw length, non-whitespace content, sentinel rejection, unique capabilities, and safe official-provider activation. Revision `0006_identity_constraints` forward-aligns a persistent database that had already applied the earlier local `0005` draft; fresh installations safely execute both revisions.

## Requirements and limits

This verifies the C-006 portions of FR-002, FR-016, NFR-010, NFR-012, P0-03, and the identity/registry part of P0-22. It does not enable Gemini, dispatch network requests, establish API entitlement, reserve budget, infer consumer-subscription access, implement manual declaration/replay semantics, or perform comparison synthesis. Those remain assigned to C-007 through C-011 and require their own gates.

No live provider, credential, external spend, P1, or P2 behavior was introduced. The implementation realizes the already-frozen registry and identity contracts, so no Change Request was required. Both migrations are forward-only: rollback uses a verified pre-migration backup and the prior application image. A problematic provider can be disabled without changing immutable historical snapshots.
