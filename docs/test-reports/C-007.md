## Delivered behavior

- The official `google-genai` SDK is pinned at 2.33.0 behind the transport-neutral
  ProviderPort. No vendor type crosses the adapter boundary.
- A Gemini qualification is fail-closed unless it has an unexpired owner-reviewed paid
  project, region, exact requested/accepted IDs, model family, token ceilings, tariffs,
  and paid no-training data profile. Blank, duplicate, stale, partial, free-tier, or
  zero/negative-bound profiles cannot send.
- Generation requires the existing C-010 AuthorizationPort. The returned grant must
  match grant/attempt/provider/model/input digest/output bound, and its one-shot
  claim/held transaction must commit before transport. Denial, mismatch, replay,
  commit failure, or qualification expiry while waiting sends no request.
- The official transport pins the Gemini Developer API, stable v1, and
  `generativelanguage.googleapis.com`; forces non-Enterprise/non-Vertex routing;
  disables redirects, environment proxies, environment backend/base selection, SDK
  retries, continuation, automatic function calls, and server-side response storage.
  One authorized invocation can therefore make at most one HTTP request.
- Timeout, quota/rate-limit, cancellation, policy, provider, and unknown-delivery
  failures are sanitized and mapped locally. No adapter retry occurs after an
  uncertain attempt.
- Successful text with a missing returned model version remains an original with
  unknown provenance and earns no family confirmation. A known model outside both
  request and qualification allowlists is rejected. Every returned raw receipt reaches
  a required observer before identity validation so C-009 can preserve mismatch
  evidence without changing ProviderPort.
- Prompt tokens map to input usage. Candidate plus thinking tokens map to billable
  output only when both are measured; incomplete usage remains null. Cost estimates
  conservatively bound UTF-8 input bytes and maximum output with upward microusd
  rounding.
- The dated account record remains disabled. The persistent registry still reports
  `google/gemini-api-candidate` as disabled, pricing unknown, and privacy blocked.

## Requirements, integration, and limits

This verifies the implementation portions of FR-002, FR-004, FR-015, FR-016,
NFR-010, P0-04, and P0-22. C-009 must provide the dedicated authorization transaction
callbacks, persist the receipt observer payload and actual transmission snapshot, and
reconcile the held reservation; it must not retry an unknown delivery. C-008 remains
the next eligible task.

The live-provider portion of P0-04/G4 remains open. The owner must supply and explicitly
approve a current Gemini project/tier/region/model/quota/tariff/data profile, a nonzero
bounded local spend policy, and a non-sensitive smoke fixture without placing the key in
chat or Git. Until then the adapter is not wired into dispatch and the registry remains
disabled. No external API call, credential, spend, public contract, migration, phase
boundary, P1/P2 behavior, or Change Request was introduced. Rollback disables the
adapter (already the default) and restores the prior application image; canonical
history and C-010 ledger records are unchanged.
