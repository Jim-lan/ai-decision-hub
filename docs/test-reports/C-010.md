# C-010 verification record

Baseline `g1-design-v2.0` at `9edbcd4b9a142d107df219bc64bd6730b39689cd`. Verified November 13, 2026. The durable checkpoint uses commit message `C-010 guard context replay and spend` and includes this record with the implementation and state indexes.

## Delivered behavior

- `ContextPort`, `BudgetPort`, and `AuthorizationPort` now have transport-neutral typed contracts. A generation request carries a durable grant identifier; no provider adapter can treat a caller-supplied eligibility boolean as authorization.
- Run admission normalizes version-1 requests, includes ordered source IDs, deadline and optional run cap in the owner-scoped idempotency digest, persists that normalized request, and preserves exact version-0 replay only when all new fields remain at legacy defaults. Unknown fields, duplicate sources, changed source order, and changed payloads fail closed.
- The existing public run endpoint remains manual-only. Official API admission and network execution remain disabled until C-007 and C-009 integrate the approved ports. Manual collection incurs no provider reservation.
- Provider-specific context requires current project consent, an allowlisted enabled registry entry, explicit current release rules for the canonical question and every selected source, and the exact frozen source order. Destination redaction occurs before a durable immutable prepared projection is stored. The record preserves sanitized model-visible bytes, ordered selected/included IDs, policy version, bounds, omissions, redactions, and SHA-256 digest; it is distinct from C-009's eventual actual-transmission snapshot.
- Dispatch revalidates the exact current sanitized projection under locked consent/source-policy rows. Revocation, expiry, redaction changes, changed essential-question handling, reduced input bounds, disabled registry state, or source drift blocks the send.
- Worst-case integer-microusd cost is rounded up and atomically reserved against optional request, run, owner UTC day/month, and provider-account call/input/output limits. Shared aliases for one provider account must use one timezone and quota ceiling; advisory locking prevents conflicting policy write skew.
- Provider daily periods use the configured IANA timezone (`America/Los_Angeles` in fixtures), including DST. Owner periods use UTC. Admission and dispatch authorization sample an authoritative clock after acquiring their critical locks, so waiting across a reset, deadline, or policy expiry cannot reuse a stale instant.
- Revalidation and authorization recompute current tariff exposure. A same-version tariff increase above the held amount blocks dispatch. Current caps and quota are checked even within the same period, and reservations cannot silently move to another provider account.
- One reservation can mint one grant and one atomic dispatch claim. A successful claim immediately transitions the unresolved liability to `held` and writes append-only hold evidence before authorization returns. It therefore carries across UTC/Pacific boundaries after a crash and cannot be blindly retried.
- Reconciliation releases only with trusted proof of non-delivery, settles exact trusted usage idempotently, preserves unknown holds, and quarantines the provider on an overrun. Known charges cannot be reduced, replayed differently, or erased by release. Usage evidence, grants, claims, prepared projections, selected source order, and reservation identity are database-protected.
- `GET /v1/usage` returns the frozen USD day/month/optional-run shape with caps and reserved/held/settled exposure. Unresolved or incomplete measured tokens remain null. Bootstrap creates the single owner's default-zero policy without overwriting a later owner decision.

## Requirements, integration, and limits

This verifies the C-010 portions of FR-013, FR-014, FR-015, FR-018, NFR-004, NFR-005, NFR-013, and the implementation portions of P0-08, P0-09, and P0-10. Cross-feature network-I/O assertions remain open until C-007/C-009 connect a deterministic provider adapter and worker.

The dispatch claimant must commit the claim/held transaction before the first network byte leaves. A crash afterward is intentionally treated as unknown delivery and is not retried. C-009 must preserve this ordering and create the actual transmission snapshot; it must not treat a prepared projection as proof of bytes sent.

No live provider, credential, external spend, P1, or P2 behavior was introduced. The implementation realizes the frozen contracts, so no Change Request was required. Revision `0007_context_budget` is forward-only: rollback disables outbound work and restores the verified pre-migration backup with the prior application image.
