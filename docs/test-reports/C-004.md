# C-004 verification record

Baseline `g1-design-v2.0` at `9edbcd4b9a142d107df219bc64bd6730b39689cd`. Verified November 12, 2026.

## Delivered behavior

- CI has a separate quality job with pinned Python tooling for Ruff, strict mypy, OpenAPI validation, JSON Schema validation, domain fixtures, and requirement/card coverage. The existing foundation job retains fresh migrations, real PostgreSQL integration, generated runtime-contract drift, HTTP entry points, browser smoke, and encrypted recovery rehearsal.
- `ProviderPort` is a pure standard-library Protocol with immutable generation, capabilities, and cost-estimate types. A boundary check rejects vendor SDK imports outside adapter locations and infrastructure imports inside the domain port.
- Two structurally typed fake adapters substitute behind the same port. Static typing checks their concrete implementations, not only the Protocol declaration.
- Versioned deterministic fixtures cover known success, successful content with explicitly unknown identity/usage, timeout, and a raw successful response whose known returned model is outside the request allowlist. The latter is normalized to a failed `invalid_response` without changing the raw fixture.
- The provider-result schema rejects vendor payload leakage and incomplete fixture shapes. Candidate and prototype/runtime provider response fixtures each include a valid case and a deliberately incompatible case that must be rejected.
- Every pytest case denies non-database/non-loopback socket connections. A regression attempts a documentation-only external IP and proves the connection is blocked before any network I/O.
- Live-provider checks remain explicit opt-in work for later cards. No provider key, paid call, consumer-chat automation, or saved reset was used.

## Requirements and limits

This verifies the C-004 portions of NFR-008 and the enabling gate portions of FR-005, NFR-007, NFR-010, P0-19, P0-22, and P0-24. It establishes reproducible contracts and CI; it does not claim complete feature behavior that belongs to later implementation cards.

C-006 and C-007 still own the production registry/adapter identity contract. C-009 owns lifecycle and preserved partial results. C-014 owns full documented endpoint runtime conformance and release fault injection. C-015 owns final offline/hybrid browser and recovery release evidence. Optional permitted live-provider qualification remains separate and cannot be satisfied by these offline fixtures.

No frozen public API or storage contract changed and no Change Request was required.
